# Existing PDF image editing

The Edit workspace lists source images on the current page. Each row shows its pixel dimensions and a thumbnail of its rendered page area. Overlapping artwork may appear in that preview; it is not an isolated image extraction. Selecting a row navigates to the image and outlines its PDF bounds. Text and vector drawings are separate content and do not appear as image entries.

`ImageEditSession` retains a selected `PDFNativeImage`, its source document and revision, the original page bounds, pending frame coordinates, and an optional replacement bitmap. X, Y, width, and height use unrotated PDF page points, matching `PageRegion`. The current frame aspect ratio is locked by default. Replacement fills the current frame; choosing a file does not silently resize it or modify the PDF. New geometry must be finite, at least one point in each dimension, and within the page crop box. An originally clipped image can still be replaced at its original placement.

`ReaderModel+Images` lists and selects images, stages replacement files, previews proposed bounds, and commits changes. Apply constructs a new PDF through `PDFNativeImageEditor.update` before replacing the document. Replacement and movement/resizing share one undo action. Remove invokes the engine's source-removal operation and likewise creates one undo action. No image cover annotation or whole-page bitmap is used for these operations.

The native engine enumerates Image XObjects, including nested Form invocations, and supplies identity tokens, source bounds, dimensions, movement eligibility, and a reason when movement is restricted. Skewed, singular, or custom-clipped placements disable geometry controls. Replacement in an original placement requires finite, positive source bounds; removal is available independently of geometry. The engine checks source identity again before rewriting. Inline images, malformed content, recursive forms, encrypted files, and restricted permissions produce explicit errors. Replacement bitmaps are limited to 80 million pixels and 32,768 pixels per dimension. Exact parser, clipping, and replacement limits are defined by its errors and covered in core image tests; unsupported inputs fail rather than flattening the page.

Pending image changes persist across page and tool navigation. Selecting another image will not implicitly discard them. A PDF identity or revision change makes the selection stale: the user must discard the pending controls and select the image again. A dirty marker draft or failed native text edit blocks beginning or applying an image edit. Errors retain the current PDF and pending image controls. Saving refuses pending image changes, and closing offers Keep Editing or Discard Unapplied Image Changes. Discarding leaves earlier applied PDF edits intact.

`ImageWorkspaceTests` uses real generated PDFs with two invocations of the same bitmap and surviving native text. It covers combined replacement/geometry save and single-step undo/redo, source-image removal/undo, invalid geometry and stale-source rollback, persistence across tool changes, pending replacement/marker/text preservation, document-save guarding, and aspect locking in both resize directions. An actual PDF view verifies selection navigation, zoomed outlines, and previews on ordinary and rotated pages. Core engine tests separately validate source content and image invocation preservation.

Preview tasks follow the complete image descriptor, including its source fingerprint, while list identifiers remain stable for selection. A document revision can arrive before the parent's descriptor list refreshes; keying the task only to that revision can reject a stale descriptor and leave a blank preview permanently. `ImageThumbnailRefreshTests` reproduces this ordering with actual SwiftUI rows in a hidden hosting window and checks rendered replacement and neighboring-thumbnail colors. The test fails with the original revision-only key and passes with descriptor identity. Preview placeholders use gray ink against white paper in either appearance.
