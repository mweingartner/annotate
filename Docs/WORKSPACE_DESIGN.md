# Annotate document workspace

## Product scope and evidence

The requested reference is [PDFgear for Mac](https://www.pdfgear.com/pdfgear-for-mac/), retrieved September 5, 2026. Its ten advertised areas are content editing, AI assistance, compression, conversion, page organization, signatures, OCR, forms, redaction, and local use without accounts, ads, or watermarks. These are vendor claims, not independent test results. Detailed source checks and platform distinctions are in PDFGEAR_RESEARCH.md.

Annotate retains its Swift 6.2+, macOS 26+, Apple-framework architecture and its composable passage markers. The next release adds a document workspace to the reader, with named, keyboard-accessible tools: Edit, Pages, Forms, Sign, Convert & OCR, Redact, and Assistant. The original marker/search panel remains available. A single trailing workspace panel keeps the PDF visible and avoids modal tool switching.

## Interaction design

- Read mode keeps native PDFKit selection, links, forms, and existing marker tags. Selecting a passage opens an annotation editor with composable categories and an explicit Add marker action. Untouched passage drafts also offer Edit PDF text and standard highlight/underline/strikeout actions. Saved tags open readable details with edit/delete actions; selected sidebar markers expose the same actions. Marker actions from workspace tools return to Read so the marker editor stays visible. Modified drafts are protected from unrelated deletion.
- Edit and Redact can select a rectangular page area directly on the canvas. The selection is clamped to a single page and displayed with an outline. Geometry fields provide an accessible alternative.
- In Edit, selecting a word, line, or paragraph opens a shared native rich text session on the page and in the sidebar. Installed font families and actual typefaces, mixed-run styles, size, color, underline, alignment, and geometry controls update selected runs. Source glyph codes are removed from content streams; CoreText replacement text is imported as native PDF text, preserving surrounding vectors, text, images, and annotations. Fixed-area editing does not reflow neighboring paragraphs. Invalid geometry uses the last valid rectangle; unsupported source mapping and overflow retain pending text with an explicit failure. Fit text height and discard actions provide recovery, and saving/finishing is blocked while an edit remains unapplied. Native text insertion, image insertion, and standard markup/shapes remain separate actions. See NATIVE_TEXT_EDITING.md and TYPOGRAPHY_DESIGN.md for exact scope and tests.
- Invisible OCR selections require a separate Edit scanned text action. This changes the supported source image's selected pixels, removes the matched hidden OCR glyphs, and inserts native visible text. It accepts an unambiguous RGB/grayscale source image with a flat background and rejects masks, skew, patterned or colorful content, neighboring text overlaps, and edge patches. It does not rasterize the PDF page; unrelated content and image invocations are retained. Lossless source-image rewriting can increase output size. This is bounded plain-background scan editing, not arbitrary image retouching or document reflow.
- Existing images have a current-page thumbnail list in Edit. Selection locates and outlines the image; replacement and frame geometry are staged until one explicit Apply action. The source invocation is rewritten or removed through the native PDF engine, preserving other page content and creating one document undo checkpoint. Aspect locking keeps the current frame proportions. Skewed or clipped placements disclose movement restrictions while allowing in-place replacement/removal. Pending controls survive tool navigation and failed operations; stale source selections cannot apply. Saving and closing require applying or explicitly discarding pending image controls. See IMAGE_EDITING_DESIGN.md for exact UI and engine boundaries.
- Pages exposes thumbnails and explicit page order, insertion, extraction, rotation, and deletion. Marker geometry follows document page transformations.
- Forms uses standard PDF widgets; Sign places electronic signatures and explicitly distinguishes them from certificate authentication.
- Convert provides a concrete format list and measured compression outcomes. OCR produces a separately saved searchable PDF. Batch jobs report results for each input.
- Redact exports a fresh, fully rasterized PDF after removing selected pixels. It discards source text, annotations, metadata, attachments, and document history. No original PDF objects are copied into the redacted export. The source remains editable and must never be mistaken for the sanitized output.
- Assistant supports Ollama, OpenAI, Claude, and optional Apple Intelligence. Local Ask/Summarize/Key details actions prepare evidence and generate in one explicit action; cloud providers always stop at Review before sending and require a separate provider-named Send action. Answers expose source-page links and expandable original passages. Settings remain available without obstructing the question composer, and source-only search works without a model.

## State and data integrity

NSDocument continues to own file lifecycle and autosave. Workspace commands use a transactional copy: serialize the current document, modify a reconstructed working copy, and publish only on success. Undo/redo restores complete document snapshots for page operations, panel form commands, content replacement, and annotations. Native canvas form edits instead register field-value undo in place, preserving the active field editor and caret. Permission checks belong to each operation (commenting, assembly, editing, copying, printing, or form entry); a generic comment permission is not treated as authorization for every tool.

Replacing the document cancels stale search and selection work, dismisses annotation popovers, reloads marker metadata, increments a document revision, clamps current page navigation, and refreshes the PDFView. Long operations expose progress/cancellation where supported. Output dialogs protect the source file from being overwritten by derived exports.

## Acceptance

Generated PDF fixtures must prove save/reopen persistence, complete undo/redo, marker page remapping, failed-operation rollback, form values, signature appearance, image/text export, compression size reporting, full-document OCR, rotated/cropped geometry, and redaction pixel removal plus absence of hidden source content. Existing marker/tag/search/export suites remain required. The installed Applications build must be exercised through real document and tool interactions, followed by artifact/signature verification and separate Git commit/push verification.

## Material limits requiring explicit disclosure

Faithful arbitrary Office layout conversion is not implemented. Certificate signing creates detached SHA-256 approval signatures and validates byte integrity separately from offline certificate trust, with explicit rejection of encrypted or already-signed inputs. Incremental co-signing, trusted timestamps, revocation checking, and archival validation remain unsupported; see `CERTIFICATE_SIGNATURES.md`. The native text engine goes beyond PDFKit's editing APIs using Core Graphics object decoding and a Swift content-stream/object-graph writer, but still has explicit encoding, source-content, fixed-layout, and signature-preservation limits. It must never be described as supporting every PDF or as complete PDFgear parity. Exact implemented formats, available hardware-dependent AI behavior, and remaining acceptance gaps belong in the final verification report.

## Accepted provider and export additions

The assistant offers local Ollama, OpenAI API keys, Claude API keys, and optional Apple Intelligence. Local generation is one action; only reviewed provider-named Send actions transmit document text to cloud APIs. Keys use macOS Keychain; provider/model settings use UserDefaults. See ASSISTANT_DESIGN.md for current authentication, transport, source coverage, and runtime evidence.

Thirteen concrete output types are implemented, including native OpenXML XLSX text worksheets and PPTX page-image slides. These formats have roundtrip/ZIP/XML checks and macOS QuickLook rendering evidence, with explicit layout and semantic limits. They do not establish the reference's claimed 30-plus outputs, nor exact Microsoft Office import/reconstruction parity.
