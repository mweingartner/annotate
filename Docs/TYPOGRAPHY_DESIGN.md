# Rich PDF typography controls

The text-editing panel has separate actions for editing actual selected PDF text and adding a new text box. The former calls the content-editing path directly; it no longer presents page rasterization as a text-editing mechanism. Font and paragraph controls appear while a text session is active. Native rich text editors on the page and in the panel share the session's attributed text and character selection.

`FontCatalog` reads installed macOS families and actual typefaces through `NSFontManager`, matching the macOS Font panel. The family chooser is searchable. The typeface menu exposes the family's available weights and slants instead of a hardcoded six-font list. Bold and italic select actual installed font variants and are disabled when the current font cannot supply the requested trait. Size, color, underline, paragraph alignment, and position/size controls are logically grouped. A compact Spacing disclosure adds letter spacing for selected characters and line/after-paragraph spacing for their paragraphs, in PDF points. An overflow message makes clipped text visible before saving.

`RichTextTypography` applies family and bold/italic changes to each selected font run. It retains each run's size and other attributes, including mixed weights/slants when changing families. Text outside the selection is preserved. The session applies formatting to the entire block when the selection is an insertion point; the panel states whether the selection or whole block will change. Native sidebar edits retain attributed text, synchronize selection without delegate feedback loops, and disallow graphic imports into the text editor.

`PDFNativeTextStyle` reads each selected source glyph's BaseFont and effective page-space size through the same content interpreter and exact selection matcher used for editing. PDFKit's attributed selection alone is insufficient: the sample's semibold San Francisco heading is reported as regular Times New Roman by PDFKit on the tested system. Subset prefixes are removed and installed PostScript names are matched exactly. Private San Francisco aliases use AppKit's system-font API with the original weight and slant. Apple-generated variable SF instance suffixes encode axis values in hexadecimal 16.16 notation; these are checked against the installed font's available axes and actual bounds, then matched to the system font or applied as font-descriptor variations. The original heading resolves to semibold at 14 points with no substitution. Supported device RGB, gray, CMYK, and ICC-based fill colors and fill opacity are read from source instructions; other colors and paragraph properties retain their attributed-selection fallback. Unicode normalization maps source glyphs, including ligatures, to complete attributed character ranges without discarding whitespace.

A font embedded in the PDF is not necessarily installed under that name on the Mac. The style reader returns `PDFNativeTextStyleResult` containing `text` and an explicit `fontSubstitutions` list. An unavailable source face uses a full installed fallback at the actual source size and provides a visible notice naming both the missing and substitute typefaces. It never silently represents regular Times as the original face. Choosing another family uses actual installed fonts. Content-stream modification, save/undo behavior, and PDF text-run persistence belong to the shared content engine and live session.

`LiveTextEdit` stores immutable attributed text and the selected character range. Selection changes refresh controls without recording a PDF edit. Alignment changes preserve each paragraph's other properties, and typing retains its spacing and indentation. Incomplete numeric dimensions keep the last valid on-page rectangle; incomplete font sizes keep the last valid run sizes. Overflow checks use CoreText's visible character range in the complete destination rectangle, matching the native PDF writer. The on-page text container has no artificial inset that could wrap or clip an otherwise fitting passage. Fit text height uses the same CoreText area, retains the top edge, and grows or shrinks downward within the page. Both editors preview actual PDF text colors against white paper with a black caret, including in dark appearance. Native content failures leave pending text visible with the exact error and a discard action; the document owner blocks finishing or saving an unapplied edit.

`TypographyTests` and `RichTextSessionTests` contain twelve tests covering installed families/faces, real bold and italic conversions, size preservation, family changes retaining style, mixed-run family/trait changes, retained colors and unselected text, invalid/empty selections, selection synchronization, paragraph spacing, insertion-point and empty-text styles, invalid geometry and font inputs, fitting text, and Unicode-safe plain-text compatibility. Tests use actual AppKit fonts and CoreText layout. There are no screenshot assertions or tests that merely compare labels.

`NativeHeadingLayoutTests` checks the untouched sample's semibold heading at all four page rotations using an actual native text view: every character is visible, the complete CoreText range fits, and native PDF replacement succeeds without adding width padding. Its second parameterized test verifies white-paper preview, preserved black PDF text, and a visible caret in light and dark appearances.

`NativeTextStyleTests` adds six tests using real PDF source fonts: the sample's variable semibold system heading, mixed bold/italic source fonts and colors, effective sizes under scaling, canonical accents and ligatures, disclosed unavailable-face substitution, and mismatch rollback. `NativeEditingReviewTests` verifies actual native text insertion twice, persistent field/focus/caret, native PDF output, and sidebar insertion with full undo/redo. It caught a real AppKit callback-order defect: selection changes arrive before text changes, so selection synchronization must wait when the text field contains characters not yet published to the session. Both native editors now follow that rule. A third test runs a generated scan through real Vision OCR, opens its initially transparent text in the app model, enables explicit scan editing, and verifies opaque, visible replacement text after save/reopen. The style result flags invisible source text for scan-mode review and normalizes its typing ink to opaque; it does not infer the scanned image's original font from the OCR layer.

Five original Apple web references and the installed `NSFontManager.h` declarations informed this implementation:

1. [Available font families](https://developer.apple.com/documentation/appkit/nsfontmanager/availablefontfamilies)
2. [Available members of a font family](https://developer.apple.com/documentation/appkit/nsfontmanager/availablemembers(offontfamily:))
3. [Convert a font to have a trait](https://developer.apple.com/documentation/appkit/nsfontmanager/convert(_:tohavetrait:))
4. [System font with a size and weight](https://developer.apple.com/documentation/appkit/nsfont/systemfont(ofsize:weight:))
5. [Font initialization by family-face or PostScript name](https://developer.apple.com/documentation/appkit/nsfont/init(name:size:))

`TextSpacingTests` verifies selected-run isolation, paragraph boundaries, zoom/unzoom preservation, and actual saved native PDF glyph/paragraph displacement. Character spacing is bounded from -10 to 30 points; additional line and paragraph spacing is bounded from 0 to 144 points.
