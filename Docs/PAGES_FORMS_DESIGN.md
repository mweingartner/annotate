# Pages, forms, and electronic signatures

This design uses five original web sources: the [PDFgear Mac product page](https://www.pdfgear.com/pdfgear-for-mac/), Apple's [PDFDocument reference](https://developer.apple.com/documentation/pdfkit/pdfdocument), [PDFAnnotation reference](https://developer.apple.com/documentation/pdfkit/pdfannotation), [list-choice widget property](https://developer.apple.com/documentation/pdfkit/pdfannotation/islistchoice), and [CMSEncoder reference](https://developer.apple.com/documentation/security/cmsencoder). The installed Apple PDFKit headers supply the exact permissions, page assembly, widget, ink-path, and drawing API contracts. The vendor page defines requested scope; its performance and security claims have not been independently validated.

## Page organization

The page panel provides a lazy thumbnail list, direct page navigation, multi-selection, page-range selection, drag/drop reordering, accessible earlier/later buttons, insertion of PDF/image/blank pages, rotation in either direction, deletion, extraction, and splitting every N pages. An empty selection targets the current page. Deleting every page is rejected. Extraction and splitting create separate PDFs. Split files are staged in a newly named folder without replacing an existing folder.

`PDFPageOrganizer` captures valid Annotate markers before page assembly. It removes those owned appearances, changes page order, maps every `PageRegion.pageIndex` to the new document, and restores each surviving marker with its identity, text, color, categories, original date, and page-space geometry. Regions on removed pages are dropped. A marker whose anchor is deleted is anchored to its first retained region. A marker with no retained regions is removed. Incoming marker identifiers are replaced only on collision; importing a document into itself produces independent markers. Incoming form names are disambiguated as `Name (import 2)`, preserving shared radio group names. PDFKit loses inherited field names during page copy, so names are explicitly restored after insertion.

Operations run against `ReaderModel.mutatePDF`'s detached working PDF. A validation or serialization failure leaves the current document unchanged. Success replaces the document, refreshes marker navigation, and registers one full-document undo snapshot. Page assembly permissions are checked separately from commenting and copying permissions.

## Forms

`PDFFormEditor` creates ordinary PDF Widget fields: text (including multiline), checkbox, radio button, dropdown, and single-selection list box. Names are validated and must be unique except for radio options sharing a group. Field geometry must fit within the page. The panel lists existing supported widgets across all pages, jumps to their pages, fills values, and removes fields. Native PDFView interaction remains available. Read-only flags, field-entry permissions, maximum length, and dropdown choices are enforced by the panel path.

PDFKit assigns initial names while configuring a widget, so the requested field name and standard text appearance are written after the annotation is attached. Form value persistence is verified by serializing and reopening real PDFs. Radio options use persisted `AnnotateRadioOption` metadata because PDFKit-generated radio appearance streams do not preserve the on-state dictionary; the metadata restores each option in Annotate and the selected value remains visible. **Risk:** generated radio-group interoperability in independent PDF readers requires validation. Certificate signature widgets and JavaScript/XFA forms are not supported as editable panel fields.

## Electronic signatures

The signature panel supports typing, pointer drawing, and local image upload. The user places and sizes the result using a selected PDF rectangle or percentage coordinates relative to the visible cropped page. A current-page toggle or page range controls multi-page placement. Ink paths convert normalized top-left drawing coordinates into each page's natural coordinate space, accounting for rotation. Typed signatures use standard FreeText and explicit default appearance data to retain the fitted font size on unrotated pages; on rotated pages, a Core Text vector overlay keeps newly placed handwriting upright. Uploaded signatures preserve original vector/text content and all native annotations while adding the image through Core Graphics; crop boxes and rotation remain intact. Use Undo and re-place to change an uploaded signature after placement.

A custom Stamp drawing subclass and a parsed image appearance copied into a new annotation both failed real save/reopen pixel checks with this PDFKit runtime. The shipping image path therefore uses page-content embedding. This path is covered by pixel checks and source-text preservation, rather than relying on an appearance subclass that only looks correct before saving.

These are visible **electronic signatures**. They do not authenticate an identity or detect later modification. The separate certificate section in the same panel adds native detached SHA-256 approval signing, using a reachable signature field, fixed ByteRange and DER Contents, and independent verification before saving a copy. Validation checks original file bytes and distinguishes signature integrity, offline certificate trust, and appended unsigned content. It requires explicit Keychain identity loading and selection; no identity is selected by default. Incremental co-signing, encrypted inputs, trusted timestamps, online revocation, and archival validation are unsupported. See `CERTIFICATE_SIGNATURES.md` for exact semantics and disposable-identity tests. Ordinary edits can invalidate a PDF's pre-existing certificate signature.

## Verification

`PageOrganizationTests` covers multi-page marker reordering, partial-anchor deletion, marker/name collisions when merging the same PDF, noncontiguous extraction, uneven splitting, inserted blank geometry, all four rotations with offset crop boxes, invalid-operation nonmutation, and strict range parsing. `FormTests` covers Unicode text, checkbox/dropdown/list-box values, radio exclusivity across saving/reopening, duplicate names, invalid bounds/choices, read-only flags, and maximum length. `SignatureTests` covers typed and ink persistence, uploaded appearance pixels and selectable source text, retained markers and form values, upright typed/image output at every quarter-turn rotation and offset crop, and validation before any page changes. `PageWorkflowTests` verifies UI-model page navigation, complete-document undo/redo, invalid-operation isolation, and displayed placement geometry for every quarter-turn rotation.
